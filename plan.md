# PyATPG Atlanta Integration Plan

This plan details the implementation of **Atlanta ATPG** for **combinational circuits** in the PyATPG framework, bypassing the heavy Cadence Genus/Modus flow for circuits without sequential logic.

---

## 1. Architectural Decisions

1. **Automatic Classification**: We detect combinational circuits programmatically:
   - If `len(circuit.flipflops) == 0`, the circuit is classified as `COMBINATIONAL`.
   - If `len(circuit.flipflops) > 0`, the circuit is classified as `SEQUENTIAL`.
2. **Dynamic Flow Switching**:
   - **Combinational Circuits**: Routed through the **Atlanta ATPG** tool. This is lightweight, license-free, and runs directly on `.bench` netlists. No scan chain insertion or Liberty libraries are required.
   - **Sequential Circuits**: Routed through the existing **Cadence Genus + Modus** toolchain, preserving the existing workflow.
3. **No Regressions**: All existing Modus files, exporters, and scripts remain unchanged to ensure full backward compatibility.

---

## 2. File and Class Structure

### A. Exporter (`pyatpg/exporters/atlanta_exporter.py`) [NEW]
A new `AtlantaExporter` class will handle the generation of files required by Atlanta:
- **Netlist Translation**: Converts the internal `Circuit` model to ISCAS `.bench` format.
- **Fault List Generation**: Formats target faults for selected suspects:
  ```text
  gate_name /0
  gate_name /1
  ```
- **Execution Script**: Generates a shell script `run_atlanta.sh` that calls Atlanta:
  ```bash
  # Targeted ATPG
  atlanta -t -f targeted_faults.flt -o targeted_patterns.pat circuit.bench > targeted_atlanta.log
  # Baseline ATPG
  atlanta -t -o baseline_patterns.pat circuit.bench > baseline_atlanta.log
  ```
- **Bundle Packaging**: Packages `circuit.bench`, `targeted_faults.flt`, `run_atlanta.sh`, and `job_metadata.json` into a zip file under `modus_jobs/` or a new `atlanta_jobs/` directory.

### B. Log Parser (`pyatpg/exporters/atlanta_log_parser.py`) [NEW]
A new `AtlantaLogParser` class will parse the stdout/log files generated by Atlanta:
- Extracts **Fault Coverage** (e.g. `Fault coverage = XX.XX%`).
- Extracts **Pattern Count** (e.g. `Number of generated test patterns = X`).
- Extracts **Total / Detected / Redundant Faults**.
- Extracts **CPU Time** (e.g. `CPU time = X.XX seconds`).
- Standardizes metrics into the exact dictionary format used by `ModusLogParser` to ensure full compatibility with the Phase 4 validation and UI heatmap visualization engines.

---

## 3. Integration Plan

### A. CLI Pipeline (`run_pipeline.py`, `run_phase3.py`, `run_phase4.py`)
- Introduce a check at the beginning of Phase 3 to read the netlist and classify the circuit.
- If combinational, instantiate `AtlantaExporter` and generate/execute the Atlanta bundle.
- In Phase 4, use `AtlantaLogParser` if the Atlanta logs are detected.

### B. Web App APIs (`app.py`, `pyatpg_app.py`)
- Under `/api/circuit/load`, store the classification status in the global/session `state` dict (e.g. `state['is_combinational'] = len(circuit.flipflops) == 0`).
- Under `/api/jobs/dispatch`, check `state['is_combinational']`.
  - If `True`, invoke the `AtlantaExporter` and run the Atlanta job (either locally or remotely via SSH).
  - If `False`, fall back to the existing `ModusExporter` and SSH run flow.

## 4. Verification Plan

1. **Combinational Circuit Validation**:
   - Run the full pipeline on a combinational ISCAS benchmark:
     ```bash
     python scripts/run_pipeline.py benchmarks/c432.v --local-only
     ```
   - Verify that an Atlanta-style bundle is generated with `.bench` and `run_atlanta.sh`.
2. **Sequential Circuit Validation**:
   - Run the full pipeline on a sequential ISCAS benchmark:
     ```bash
     python scripts/run_pipeline.py benchmarks/scan_s27.v --local-only
     ```
   - Verify that the Modus/Genus bundle is generated exactly as before, with no changes or errors.
